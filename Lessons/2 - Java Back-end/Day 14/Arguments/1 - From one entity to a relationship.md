# From one entity to a relationship

## Learning Objectives

- Start from the completed Day 13 JPA application.
- Describe where a foreign key belongs in a many-to-one relationship.
- Keep the existing MVC request route while the data model grows.

## The limit of one entity

Day 13 maps each `Employee` object to one row in `employees`. The entity contains simple values such as `firstName`, `lastname`, `location` and `email`.

That model cannot answer a new question: which department does an employee belong to? Storing the department name directly on every employee would repeat the same department data and make updates inconsistent.

We need two entities and a relationship between them:

```text file:"Employee and department relationship"
one department
    <- referenced by many employees
```

In PostgreSQL, the foreign key belongs on the many side:

```text file:"Relationship columns"
departments
    id (primary key)
    name
    location

employees
    id (primary key)
    first_name
    lastname
    location
    email
    department_id (foreign key -> departments.id)
```

Each employee row stores one `department_id`. Several employee rows may store the same value.

## Begin from the live repository

Clone the completed Day 13 application into a new folder:

```sh file:"Clone the starting project"
git clone https://github.com/WOWS-Inc/java-jpa-hibernate-lombok.git java-jpa-hibernate-relationships
cd java-jpa-hibernate-relationships
```

The project already contains the Devbox configuration, PostgreSQL connection, JPA dependency and this package structure:

```text file:"Existing MVC packages"
jpa-api/src/main/java/com/booleanuk/api/
    model/
    repo/
    service/
    controller/
```

Keep that route through the application:

```text file:"Relationship request route"
request
    -> controller
    -> service
    -> Spring Data repo
    -> Hibernate
    -> PostgreSQL
```

The relationship changes the model and the SQL generated by Hibernate. It does not give the controller permission to skip the service.

Because this lesson starts in a new project folder, do not add a database refresh, reset or wipe step. Keep `ddl-auto: update` and let Hibernate create the missing structure for this lesson.

Use one entity for independent data. Add a relationship when one entity must refer to another entity with its own identity and fields.
